## Session 15 — Phase 2 Stage 2.3: Separate core and i18n helpers

### Session information

- **Date:** 2026-11-22
- **Phase:** 2 Stage 2.3
- **Objective:** Split mixed responsibilities in `helpers.ts` without public API or algorithm changes

### Investigation — function classification

| Function | Category | Destination |
|----------|----------|-------------|
| `getDaysInMonth` | Core/calendar | `src/utils/calendar.ts` |
| `parseDateInput` | Core/calendar | `src/utils/calendar.ts` |
| `localizeDigits` | i18n | `src/utils/localization.ts` |
| `localizeMonth` | i18n | `src/utils/localization.ts` |
| `nepaliDigitsToEnglish` | i18n | `src/utils/localization.ts` |
| `getDateFormatPatterns` | Formatting / presentation (parse patterns) | `src/utils/localization.ts` |

No generic multi-layer utilities required a third neutral module beyond the re-export shim.

**Duplication:** Datepicker already uses `getDaysInMonth` (Stage 2.2); no duplicate month-length logic. Formatter still owns `toNepaliDigits` (separate public API).

**Circular-import risk:** None — `calendar` → constants/types only; `localization` → constants/types only; neither imports the other; converters import `calendar` only; UI imports both; `helpers` re-exports both.

### Dependency graph

**Before**

```
helpers.ts ──► calendar-data, types
  ├── getDaysInMonth, parseDateInput
  └── localize*, nepaliDigitsToEnglish, getDateFormatPatterns

converters, ui, index ──► helpers
```

**After**

```
calendar.ts ──► calendar-data, types          (no i18n, no DOM)
localization.ts ──► calendar-data, types     (no calendar helpers, no DOM)
helpers.ts ──► calendar + localization       (re-export shim only)

bs-day-index, bs-to-ad ──► calendar
NepaliDatePicker ──► calendar + localization
index ──► calendar + localization            (public facade unchanged)
tests (compat) may still import helpers
```

### daysInBsMonth fallback (Stage 2.2 clarification)

Numeric constant `30` only when `getDaysInMonth` throws (out-of-range year for adjacent-month grid padding). Does **not** read `BS_CALENDAR_DATA` or reimplement month-length arithmetic.
